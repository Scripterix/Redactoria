# Architecture Decision Records

ADRs record decisions that materially affect system boundaries, data ownership,
technology choices, or future implementation constraints. They explain why a
decision was made and what consequences follow from it.

## Adding a decision

Create a new numbered file instead of rewriting the history of an accepted ADR.
If a decision changes, mark the previous record as superseded and link both records.
Exploratory ideas belong in the [Futureboard](../futureboard/README.md) until accepted.
