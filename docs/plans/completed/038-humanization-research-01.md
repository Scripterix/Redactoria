# Plan 038 — Humanization research 0.1

Status: **ACTIVE**

## Scope

Research established editorial guidance for AI-assisted technical prose and update
`docs/humanization.md` as a policy/research artifact. Focus on naturalness,
readability, concrete language, author voice and reader value — never detector
evasion or false human authorship.

## Boundaries

- Do not edit public articles, drafts, Writer or Critic contracts.
- Do not implement Humanizer logic, metrics or an automatic rewrite.
- Do not promote LAB material, publish, commit, push or deploy.
- Treat each prospective rule as an editorial signal requiring context, not a
  mechanical replacement.

## Deliverables

1. Source-backed research note in LAB.
2. Updated `humanization.md`: covered rules, genuine gaps, possible duplicates,
   ten-priority Humanizer 0.1 proposal, before/after examples and exceptions.
3. Completed plan with the result recorded.

## Result

Completed on 2026-10-16. Research used Google Search Central, Google Developer
Documentation Style Guide, Microsoft Writing Style Guide and GOV.UK guidance.
`docs/humanization.md` now records the evidence, covered rules, eight genuine
gaps, possible duplicates, a ten-rule future rubric, before/after examples and
exceptions. The accompanying LAB report is
`lab/reports/humanization-research-0.1.md`. No article, CONTENT, Writer/Critic
contract, Humanizer implementation, publication, Git or deployment changed.
